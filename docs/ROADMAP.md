## 每个业务模块的接入方法

先写数据迁移与接口契约，随后实现服务器校验、权限和事务，再替换对应前端本地状态，并执行真实数据库集成测试。一个模块接入完成后再切换数据来源，不让同一页面同时写入本机和服务器而造成分叉。

## 从原型 2.25 到正式服务

1. **先通过一条复练路径验收。** 用 P02 → P07 → P02 验证设置目标、保存自评、过期后仍能换题复练与历史回看。接入前选少数教育管理高频主题试用，观察考生能否在陌生案例里独立写出之前遗漏的得分点。复练间隔和建议用时以实际反馈校准。
2. **个人学习数据入库。** 服务器从登录会话确定归属。目标和草稿检查修订号；作答、自评与复练安排在同一事务提交。每主题保留一个待复练任务，关联来源作答、题目修订与要点原文。旧目标和同版本旧草稿可手动带入，历史作答的批量迁移仍需设计来源预览与冲突规则。上线前验收备份恢复后的学习记录及复练状态。
3. **接入服务器试用版。** 开卷时保留题目、分值和量表。纸笔手填分单独标注。P13 复练来源关联同账号的终结答卷。试用采用教育管理教学卷，目标地区、考纲和仿真评分另行核验。

## 关键验收场景

- 新账号不会出现他人练习记录；学员调用维护 API 必须被服务器拒绝；退出和过期会话失效。
- 维护者发布的选择/判断/填空/简答可在另一账号看到；草稿和归档不会出现在用户列表；原题下的变式关系正确。
- 两名维护者同时编辑时通过 `expectedRevision` 拒绝覆盖更新。已作答题目改版后，旧答卷仍可阅读旧题与旧参考。
- 仅打开题目不能自动改变为已掌握；评分对错和自评颜色独立；题目列表支持薄弱题筛选。
- 跨日、考试当天是否计入、过去日期和每日时长计算保持原型行为；已完成时数与计划容量分开。
- 重复交卷只保留一条记录。在线复盘须先交卷，主观题待评时暂不显示总分。选择结束作答并查看答案时，生成单独标记的纸笔自核记录。
- 时政来源未核验不得发布；政策失效后可定位受影响题目，新版不覆盖基础答案和旧作答。
- 在干净服务器按文档拉取指定 tag 并启动；从备份恢复后记录完整；升级后健康检查与版本相符。
