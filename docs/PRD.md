## 1. 产品目标与适用范围

备考有方把备考经验整理成其他人能重复使用的学习工具。用户先了解知识结构，再通过题目主动回忆、对照参考、自评掌握，按需练习同组变式，最后用整套模拟答卷检查表达和应用。

首批教学内容围绕教育管理备考，覆盖组织与管理、家校社协同、评价等主题。当前主题及样卷具有教学示例性质。推广到其他考试前，需要补齐相应知识、题库、来源和评分依据。

产品需要解决以下问题。

- 用户知道考试日期，却难以把剩余天数换算成可投入的复习时间。
- 用户看过知识后难以确认自己能否独立提取，也难以快速找到薄弱题。
- 原题、变式和模拟卷混在一个连续流程里，用户难以理解自己所在的位置。
- 题库需要经常更新，维护者需要按题型录入、预览、发布和追溯旧版。
- 时政内容更新后，需要知道依据是什么、适用哪些题、加在答案什么位置。

当前版本适用于受控的账号测试和共享题库验证。正式稳定版还需完成个人记录云同步、服务器模拟答卷、时政审核发布等后续事项。

## 3. 用户角色与权限

| 角色 | 主要任务 | 权限范围 |
| --- | --- | --- |
| 学员 | 设置目标、学习知识、练题、自评、模拟与复盘 | 访问学习空间和已发布题库，查看本人的记录 |
| 维护者 | 新增题目、维护变式、校对答案、管理发布、整理时政材料 | 使用学习空间和内容维护功能，无账号管理权限 |
| 管理员 | 开通和停用账号、管理内容及运行环境 | 具有维护权限和账号管理权限 |

首次管理员通过部署初始化工具建立。管理员在网页开通后续账号，设置邮箱、姓名、初始密码和角色。初始密码至少 12 位，用户可在登录后修改。停用账号或修改密码后，旧会话撤销。当前网页支持开通及启停账号，角色在开通时指定。

服务器必须执行权限校验，直接输入维护页面地址或自行调用接口均不能绕过权限。后续服务器个人记录应从会话确定归属，学员只能读取和修改本人记录。

## 4. 信息架构与导航

```text
登录
└─ 学习空间
   ├─ 首页
   │  ├─ 考试目标与倒计时
   │  └─ 可用时间与任务建议
   ├─ 知识学习
   │  └─ 知识地图
   │     └─ 主题详情、知识卡与关联题组
   ├─ 题目练习
   │  ├─ 全部题目 / 薄弱题筛选
   │  └─ 题组
   │     ├─ 原题作答、核对、自评与历史
   │     └─ 关联变式作答、核对、自评与历史
   └─ 模拟考试
      ├─ 试卷库 → 整套作答 → 检查交卷
      └─ 答题记录 → 某次已交答卷 → 评阅与复盘

维护工作台（维护者、管理员）
├─ 题库管理 → 新增 / 编辑 / 预览 / 发布 / 下架 / 历史
├─ 时政融合规划 → 未核验草稿与效果预览
└─ 账号管理（管理员）
```

导航应遵守以下规则。

- 知识地图作为知识学习的子级展示。
- 题目列表是练习入口，用户自由选择原题或变式。原题与变式具有双向入口，各自保留作答草稿。
- 题目练习和模拟考试是平级模块。完成单题后，由用户选择是否去模拟考试。
- 复盘绑定某次已交卷记录。未提交过答卷时，答题记录显示空状态并提供试卷入口。
- 从复盘进入关联题组练习时，保留原答卷，允许回到该次复盘。
- 页面通过侧栏子级、面包屑和返回入口共同说明当前位置。

## 5. 首页与时间预算

**需求 HOME-01，当前本机可用。** 首页单独保留倒计时区域，展示考试日期、距离考试天数、每日可投入时间、可备考日数和预计剩余总小时。

用户可以选择考试日期，每日复习时长提供 30 分钟、1 小时、1.5 小时、2 小时、3 小时、4 小时选项，并选择是否计入考试当天。修改后点击保存或更新才生效。

计算规则如下。

- 以浏览器当前本地日历日期为今天，按日计算，不按剩余分钟折算。
- 可备考日数 = 考试日期与今天的日历天数差 + 是否计入考试当天的 1 天，最小为 0。
- 预计剩余总小时 = 可备考日数 × 每日复习小时，最多展示两位小数。
- 今天按一整天计入。选择包含考试当天时，考试在今天会得到 1 个可备考日。
- 未设置目标时展示设置引导。无效日期和过去日期不允许作为新目标保存。
- 已保存的日期自然过期后，显示日期已过并提示更新。页面跨日或重新回到前台时更新预算。
- 页面注明该数值是计划可投入时数。当前没有实际学习时长统计。

例如，今天为 11 月 10 日，考试为 11 月 20 日，每天 2 小时。计入考试当天时为 11 天、22 小时，不计入考试当天时为 10 天、20 小时。

**需求 HOME-02，当前本机可用。** 根据剩余总时数推荐学习范围和每日安排。

| 可用总时数 | 建议 | 理解知识 / 提取复习 / 作答训练 / 自评调整 |
| --- | --- | --- |
| 少于 20 小时 | 精简备考，优先 S 级与薄弱题 | 15% / 40% / 35% / 10% |
| 20 至不足 60 小时 | 均衡备考，巩固 S 级并推进 A 级 | 25% / 30% / 35% / 10% |
| 60 小时及以上 | 系统备考，多轮提取和变式，再扩展 B 级 | 30% / 25% / 35% / 10% |

前三类任务分钟数向下取整，余下分钟全部归入自评调整，合计等于用户每日预算。距考试不超过 7 天时额外提示优先复习和输出。每项任务提供对应学习或练习入口。阈值是当前产品体验规则，尚无学习效果验证，未来可结合覆盖率、掌握情况和实际用时调整。

## 6. 知识学习

**需求 KNOW-01，当前为静态教学内容。** 用户先进入知识地图，看到主题结构，再进入主题详情查看知识解释、记忆支点、应用方式和关联题组。

知识卡应帮助用户理解知识之间的关系，以及如何在答题时展开。主题与题组通过明确入口关联，进入题目后仍能识别其知识主题。优先级 S / A / B 用于表达学习先后顺序，不与掌握程度颜色混用。

后续内容维护需支持主题、知识卡、记忆支点和题目关联的版本管理。当前维护端只能更新题库，知识主题新增及结构调整需要后续开发。

## 7. 题目练习

### 7.1 题目菜单与掌握状态

**需求 PRA-01，当前题库来自服务器，自评记录在本机。** 列表先展示题干、题型、所属主题、关联变式、掌握状态和最近接触时间。用户可以搜索题干，按知识主题、题型和掌握程度筛选。

| 状态 | 显示要求 | 产生条件 |
| --- | --- | --- |
| 未接触 | 白色卡片及文字标签 | 当前题目版本尚无接触记录 |
| 待自评 | 独立待评样式及文字标签 | 已打开或已作答，尚未完成掌握自评 |
| 想不起来 | 薄弱颜色及文字标签 | 用户选择该自评 |
| 有点模糊 | 与薄弱、掌握明确区分的颜色及文字标签 | 用户选择该自评 |
| 能独立回忆 | 已掌握颜色及文字标签 | 用户选择该自评 |

打开题目只能变为待自评。客观题答对不自动变为已掌握。原题和每道变式分别记录掌握状态；筛选命中变式时保留其所属题组并提供直接入口。仅凭颜色不能成为识别状态的唯一方式。

### 7.2 单题闭环

**需求 PRA-02，当前可用。** 选择题目 → 按题型作答 → 请求核对或展开参考 → 对照要点 → 选择掌握自评 → 保存本次记录 → 返回列表或选择同组变式。

作答前，服务器返回的题目不包含标准答案、参考答案或评分要点。用户留下有效回答后才可获取参考。简答返回参考答案和要点，由用户逐项对照标记，再选择掌握程度。改变答案后，需要重新核对才能再次保存自评。

草稿、选择的要点、自评、核对结果、答题时间和题目快照保存在当前账号的浏览器记录中。服务器负责客观核对，目前不保存这些个人记录。用户可以查看旧练习；题目改版后重新评估新版，保留旧版草稿和练习快照。

### 7.3 评分规则与 AI 边界

**需求 PRA-03，客观题已接入服务器，简答为人工自评。**

| 题型 | 当前核对规则 |
| --- | --- |
| 单选 | 选择与正确选项一致得满分，否则 0 分 |
| 多选 | 选项集合完全一致得满分，漏选、错选均为 0 分 |
| 判断 | 与维护者设定的正确或错误一致得满分，否则 0 分 |
| 填空 | 逐空匹配已录入的可接受答案，按正确空数等比例计分，结果保留两位小数 |
| 简答 | 返回参考答案和要点，状态为待人工评估，当前不生成语义评分 |

填空匹配忽略空格、英文大小写及全半角差异，其他等价表述由人工复核。当前使用文字输入，语音输入尚未接入。

**需求 PRA-04，规划待开发。** 若后续引入 AI 辅助评阅，应以题目版本、参考答案、评分点、满分和用户原答作为输入，输出已覆盖点、部分覆盖点、待补齐点及对应原答依据。语音场景先转写，允许用户确认转写内容后提交。

AI 建议须与用户自评及人工评分分别展示，保留模型与评分规则版本。无可靠依据、超时或调用失败时显示待评或人工对照入口。题目文本、学员答案及引用材料均作为数据处理，不能改变评阅规则。该能力的提供商、费用、数据处理方式和评分可靠性需要在接入前确认。

## 8. 四类题型与维护工作台

### 8.1 公共字段与模板

**需求 BANK-01，已接入服务器。** 每题有稳定题号、内容版本、题型、主题、优先级、标题、题干、分值、资料性质、来源链接和解析。变式另外指定所属原题，必须属于同一主题，禁止变式再挂变式。

分值大于 0 且不超过 100。资料性质当前支持教学编题、考生回忆、官方材料、AI 新编。官方材料和考生回忆要求填写可追溯来源；填写来源链接时必须是有效 HTTP 或 HTTPS 地址。“AI 新编”是资料性质标签，当前没有自动出题能力。

| 题型 | 维护表单 | 用户作答形式 | 发布检查 |
| --- | --- | --- | --- |
| 选择 | 单选或多选、2 至 8 个选项、正确选项、解析 | 单选按钮或多选框 | 编号和内容不重复，正确项必须存在，单选恰有一个答案，解析必填 |
| 判断 | 题干、正确或错误、判断依据 | 正确或错误二选一 | 答案有效、依据必填 |
| 填空 | 含 `{{1}}` 等空号的题干、逐空可接受答案 | 每空一个输入框 | 1 至 5 空，空号从 1 连续编号且各出现一次，每空至少一个有效答案 |
| 简答 | 题干、参考答案、评分要点 | 多行文本输入 | 参考答案和至少一个非空要点必填 |

例如，填空题可录为“管理活动包括 `{{1}}` 和 `{{2}}`”，维护者分别为两空录入允许答案。用户界面显示两个编号空位，用户无需输入 JSON 或模板标记。

### 8.2 日常维护流程

**需求 BANK-02，已接入服务器。** 题库列表 → 选原题或新增题目 → 选择题型 → 填写公共字段和题型字段 → 保存草稿 → 预览 → 检查发布条件 → 发布 → 用学员账号验证可见内容。

草稿允许分次补齐，至少有标题或题干。发布时由后端重新检查字段完整性和父子关系。维护者可以保存草稿、发布、下架、查看版本历史。当前没有批量导入、回收站和网页知识主题管理，相关扩展需单独规划。

### 8.3 更新与历史规则

**需求 BANK-03，已接入服务器，个人练习快照当前在本机。**

- 保存草稿不改变学员正在使用的已发布版本。
- 内容修订生成新版本，历史修订保留，记录操作人和时间。
- 两名维护者编辑同一题时，后提交者若依据旧修订号保存，返回冲突，保留编辑内容供重新处理。
- 发布变式前，同主题的所属原题必须已发布。原题下架后，其变式从学员可见题库一起隐藏。
- 题目更新后，旧作答继续引用原题目快照和原评分依据。
- 本期维护者与管理员均可直接发布题目。题库的独立审核角色和双人审批尚未实现。

## 9. 模拟考试、评阅与复盘

**需求 EXAM-01，当前为本机教学样卷。** 试卷库展示试卷名称、题量、题型、分值及作答说明。当前固定样卷为 5 道题、30 分，含客观题和主观题，具体题型配置以该样卷内容为准。维护端四类题型模板与未来试卷组合能力分别建设。

用户开始或继续同一份模拟答卷，按题作答，通过答题卡自由切换。答题卡分别说明当前题与已填答案，已填写标记不表示正确。作答中保留草稿，不显示参考答案。

**需求 EXAM-02，当前本机可用。** 交卷前展示全卷作答清单、未答题和确认操作。完全空白的答卷不生成记录；至少一题有回答并确认后，生成一次答卷。保留开始时间、交卷时间、用时和各题原答，未答题按 0 分计。

交卷后客观题按教学答案核对，主观题由用户对照量表逐点评分。主观题未评完时显示待评阅，不展示完整总分。当前参考分可以人工调整，不能据此当作具有防篡改能力的正式考试成绩。

**需求 EXAM-03，当前本机可用。** 复盘显示某次答卷的逐题原答、参考答案、评分依据、得分和关联复练入口。无该次已提交记录时显示空状态。下一步建议必须依据这份答卷的实际得分和待评项生成。

**需求 EXAM-04，规划待开发。** 后续支持维护端组卷、各题型组合、题量与分值检查、服务器保存草稿、固定试卷及题目版本、幂等交卷、云端评阅和复盘。反复点击或网络重试只生成一份交卷结果。已提交答卷保留原答，评分修订追加记录。正式计时策略、断线续考规则及主观评阅角色需在该阶段确认。

## 10. 时政与政策融合

### 10.1 使用方式

**需求 POL-01，当前只支持未核验草稿及预览。** 维护者选择题目，录入政策名称、来源日期、原文链接、引用片段、原答案插入位置、拟增补表达和适用范围，查看插入效果并保存本机草稿。

简答题保留基础答案，在明确段落后增加可展开的时政表达，展示依据、时间和适用边界。选择、判断、填空若因政策变动影响正确答案，需生成题目新版并重新核对。

### 10.2 正式内容流程

**需求 POL-02，规划待开发。** 录入资料 → 核验来源及适用期 → 关联题目版本 → 编写增补 → 人工审核 → 发布 → 到期复核或停用。

政策文件与时事案例分别登记。政策记录发布单位、原文、发布日期、生效及失效时间、适用地区和对象。时事案例记录事实、发生时间、报道来源和适用主题。

融合关系关联政策版本、题目版本、基础答案位置、增补句、引用片段、适用范围及审核记录。一个来源可关联多题，一题可关联多个来源。待核验或待审核内容不能出现在学员端。题目或来源改版后，原关系进入待复核；来源失效时列出受影响题目供处理。历史答卷保留当时引用，不因新政策自动重算。

独立审核角色、到期提醒渠道和复核频率在该阶段确认。详细设计见[时政融合规划](POLICY_INTEGRATION_PLAN.md)。

## 11. 数据归属、异常与运行要求

### 11.1 数据归属

| 数据 | 当前保存位置 | 后续要求 |
| --- | --- | --- |
| 账号、会话、题目修订、发布历史和审计 | 服务器 PostgreSQL | 备份恢复、权限隔离、历史可追溯 |
| 考试目标、练习草稿、自评、单题历史 | 当前浏览器，按账号隔离 | 接入服务器，处理多设备更新冲突 |
| 模拟草稿、答卷、参考评分 | 当前浏览器，按账号隔离 | 服务器保存完整答卷与评分历史 |
| 未核验时政草稿 | 当前浏览器 | 接入共享资料库、审核与发布 |
| 知识卡和教学样卷 | 前端静态内容 | 接入可维护且版本化的内容服务 |

当前本机数据受浏览器和站点来源隔离。更换电脑、浏览器、访问域名，或清理站点数据，可能无法看到原记录。页面应清楚说明保存位置。未来迁移旧记录时，需要显式确认账号归属和导入内容。

### 11.2 异常与空状态

| 场景 | 用户应看到的结果 |
| --- | --- |
| 无题目或无筛选结果 | 空状态及清除筛选入口 |
| 尚无交卷记录 | 引导选择试卷，复盘入口不生成虚构内容 |
| 会话过期或账号停用 | 重新登录提示，停止读取受保护内容 |
| 权限不足 | 明确权限提示，服务器拒绝请求 |
| 题目改版或维护冲突 | 明确版本提示，保留用户草稿，刷新后再处理 |
| API 或数据库不可用 | 服务错误及重试入口，运维可通过健康接口和日志定位 |
| 浏览器存储写入失败 | 提示当前保存失败与可能丢失，不能持续显示保存成功 |
| 站点地址不匹配 | 明确访问入口提示，由部署者核对站点地址配置 |

### 11.3 运行与部署

产品支持通过同一台主机运行网页、API 和 PostgreSQL。当前使用 React 网页、Node.js/Fastify API、PostgreSQL、Docker Compose 和 Nginx。默认开发前端 43126、API 43127、部署网页入口 43128。

浏览器通过统一网页入口访问 API。配置中的 `APP_ORIGIN` 要与浏览器实际使用的协议、域名和端口一致。公网测试采用 HTTPS 入口并设置 `ALLOW_INSECURE_HTTP=false`。`http://` 配合禁止 HTTP 会导致 API 启动失败，上游网页请求可能收到 502。

cpolar 测试时，把其公网 HTTPS 来源填入部署配置，并映射本机网页端口。当前只配置单一来源，域名变化后需要更新配置并重建 API 容器。多来源同时登录是后续独立需求，需要明确定义允许列表。

部署支持指定 Git 标签升级、检查版本和就绪状态、备份恢复数据库。目标稳定版需完成恢复演练及实际负载验证。当前未建立并发容量、响应时间和可用性承诺。具体操作见[部署说明](DEPLOY.md)。

## 13. 后续优先级与待确认事项

以下顺序沿用工程实施规划，作为建议排期，不包含交付日期承诺。

| 顺序 | 范围 | 交付结果 |
| --- | --- | --- |
| 1 | 个人学习记录云同步 | 目标、草稿、练习、自评、历史跨设备一致，处理旧记录迁移与冲突 |
| 2 | 服务器模拟考试 | 维护端组卷、冻结版本、服务器答卷、幂等交卷、评阅和复盘 |
| 3 | 时政内容治理 | 共享来源库、核验、审核发布、失效复核和引用追溯 |
| 4 | 稳定版验收 | 权限回归、恢复演练、目标设备测试、容量验证、移除工程预览标记 |
| 可选 | AI 辅助评阅和语音输入 | 明确评分标准、转写确认、费用和失败处理后单独接入 |

需要在对应阶段确定的事项包括正式考试与内容范围、题库责任人、主观评阅者、政策审核者、试卷时限和断线规则、固定公网域名、多来源访问需求、并发测试规模，以及 AI 服务和数据处理方式。

当前没有支付、会员、公开注册、邮件服务、批量题库导入、复杂组织管理和移动原生应用的已确认交付要求。
